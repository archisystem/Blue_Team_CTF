# DanaBot --- CyberDefenders Blue Team CTF

> **Категория:** Network Forensics\
> **Сложность:** Easy\
> **Основные инструменты:** Wireshark, VirusTotal, NetworkMiner /
> ANY.RUN (при необходимости)\
> **Цель:** расследовать заражение по сетевому дампу PCAP, определить
> начальный вектор атаки, извлечь вредоносные файлы и зафиксировать IOC.

-   **Лаборатория:**
    https://cyberdefenders.org/blueteam-ctf-challenges/danabot/
------------------------------------------------------------------------

## 1. Сценарий

SOC обнаружил подозрительную сетевую активность. По условию
лабораторной, рабочая станция могла быть скомпрометирована, а
злоумышленник мог загрузить дополнительные вредоносные компоненты.

Задача аналитика Blue Team --- изучить PCAP, восстановить
последовательность событий, извлечь подозрительные файлы и собрать
индикаторы компрометации (IOC).

## 2. Что нужно было сделать

1.  Открыть PCAP в Wireshark.
2.  Отфильтровать HTTP-трафик и найти подозрительные запросы.
3.  Проверить DNS-запросы и адреса серверов, с которыми связывался
    компьютер.
4.  Изучить HTTP-ответ и имя загружаемого JavaScript-файла.
5.  Экспортировать переданные по HTTP файлы.
6.  Рассчитать хеши файлов и проверить индикаторы через VirusTotal.
7.  Проанализировать JavaScript, чтобы понять, как загружался и
    запускался следующий этап вредоносной программы.
8.  Составить краткую цепочку атаки и сохранить IOC.

## 3. Инструменты и команды

### Wireshark

Открыть PCAP через **File → Open**.

Полезные display-фильтры:

``` text
http
dns
ip.addr == 62.173.142.148
http.request
http.response
```

Чтобы посмотреть обмен данными, выбрать интересующий пакет и открыть
**Follow → HTTP Stream** (или **Follow → TCP Stream**, если HTTP Stream
недоступен).

Чтобы извлечь файлы из дампа:

**File → Export Objects → HTTP**

Сохранить подозрительные объекты в отдельную папку для анализа. Не
запускать извлечённые файлы на основной системе.

### Linux: вычисление хешей

После сохранения файла в лабораторную папку:

``` bash
sha256sum allegato_708.js
md5sum resources.dll
file allegato_708.js resources.dll
```

### VirusTotal

Искать домен, IP-адрес или хеш файла. Результаты стороннего сервиса ---
дополнительный источник сведений, а не самостоятельное доказательство
заражения. Не загружать конфиденциальные файлы в публичные сервисы без
разрешения.

## 4. Результаты расследования

### Вопрос 1. Какой IP использовался при первоначальном проникновении?

В PCAP обнаруживается DNS-запрос к домену:

``` text
portfolio.serveirc.com
```

В ответе DNS указан адрес:

``` text
62.173.142.148
```

**Ответ:** `62.173.142.148`

### Вопрос 2. Как назывался вредоносный файл начального этапа?

В HTTP-обмене обнаруживается JavaScript-вложение с именем:

``` text
allegato_708.js
```

В некоторых представлениях HTTP-объект может отображаться под именем
`login.php`, поэтому ориентироваться нужно также на заголовки HTTP и
содержимое потока.

**Ответ:** `allegato_708.js`

### Вопрос 3. Каков SHA-256 хеш первого вредоносного файла?

Экспортировать объект из Wireshark и выполнить:

``` bash
sha256sum allegato_708.js
```

**Результат:** `847b4ad90b1daba2d9117a8e05776f3f902dda593fb1252289538acf476c4268`

### Вопрос 4. Какой процесс запускал вредоносный файл?

Вредоносный JavaScript использует Windows Script Host. В цепочке запуска
следует различать процесс, который исполняет исходный сценарий, и
программу, которую сценарий вызывает для запуска загруженной DLL.

**Ответ:** `wscript.exe`

Пример цепочки:

``` text
wscript.exe → rundll32.exe → загруженная вредоносная DLL
```

### Вопрос 5. Какое расширение было у второго вредоносного файла?

JavaScript загружает дополнительный компонент с адреса:

``` text
soundata[.]top/resources.dll
```

**Ответ:** `.dll`

Домен выше приведён в обезвреженном виде, чтобы случайно не перейти по
подозрительному адресу.

### Вопрос 6. Каков MD5 хеш второго вредоносного файла?

Экспортировать DLL из HTTP-объектов и вычислить хеш:

``` bash
md5sum resources.dll
```

**Результат:** `e758e07113016aca55d9eda2b0ffeebe`

## 5. Как работала атака

По артефактам лабораторной восстанавливается следующая
последовательность:

1.  Компьютер обращается к подозрительному домену
    `portfolio.serveirc.com`.
2.  Сервер передаёт JavaScript-файл `allegato_708.js`.
3.  Сценарий использует объекты Windows Script Host и загружает
    следующий компонент --- DLL.
4.  DLL сохраняется на диск; в коде сценария присутствует запуск через
    `rundll32.exe`.
5.  Скрипт пытается удалить собственный файл, что может затруднить
    последующий анализ.

## 8. Итог

В этой лабораторной отрабатывается базовый процесс сетевой форензики: от
подозрительного DNS/HTTP-запроса до извлечения файлов, проверки
индикаторов и реконструкции цепочки запуска.

Для Blue Team важно не просто найти подозрительный IP или файл, а
подтвердить выводы несколькими артефактами: сетевым обменом, содержимым
файла, хешами и контекстом исполнения.
