# CyberDefenders XLMRat — пошаговый разбор

## О лабораторной

- **Платформа:** CyberDefenders
- **Лабораторная:** [XLMRat](https://cyberdefenders.org/blueteam-ctf-challenges/xlmrat/)
- **Направление:** Blue Team / SOC / Network Forensics
- **Основные задачи:** анализ PCAP, поиск подозрительных HTTP-запросов, исследование загружаемых файлов, извлечение IOC и анализ вредоносного скрипта.

## 1. Подготовка лабораторных файлов

После скачивания архива с материалами лабораторной проверил, где находятся файлы:

```bash
cd ~/Downloads
ls -lh
```

Создал отдельную папку и распаковал архив (имя архива нужно заменить на фактическое):

```bash
mkdir -p ~/labs/xlmrat
unzip ИМЯ_АРХИВА.zip -d ~/labs/xlmrat
find ~/labs/xlmrat -type f
```

**Цель:** найти сетевой дамп `.pcap` или `.pcapng` и другие файлы, предоставленные лабораторной.

> Подставляй фактические имена файлов из своей лабораторной. Не запускай подозрительные исполняемые файлы или скрипты на основной системе.

## 2. Открыл PCAP в Wireshark

Открыл файл PCAP в Wireshark и начал анализ сетевых соединений.

Для просмотра HTTP-трафика использовал фильтр:

```wireshark
http
```

**Зачем:** HTTP-пакеты могут показать, какие ресурсы запрашивал хост и какие данные возвращал сервер.

## 3. Нашёл HTTP GET-запросы

Чтобы посмотреть GET-запросы от исследуемого хоста, использовал фильтр:

```wireshark
http.request.method == "GET" && ip.src == 10.1.9.101
```

В материалах опубликованного разбора рассматриваются запросы к:

```text
/xlm.txt
/mdm.jpg
```

**Что проверяется:**
- URI запрашиваемого ресурса;
- IP-адрес назначения;
- порт назначения;
- HTTP-заголовок `Host`;
- содержимое ответа сервера.

**Результат для проверки в PCAP:** запросы к `xlm.txt` и `mdm.jpg`. Необходимо подтвердить их наличие в собственном дампе.

## 4. Исследовал HTTP Stream

Для изучения содержимого запроса и ответа:

1. Выбрал нужный HTTP-пакет.
2. Нажал правой кнопкой мыши.
3. Выбрал **Follow → HTTP Stream**.
4. Проверил HTTP-заголовки и тело ответа.
5. Изучил, какие данные передаются от сервера.

**Зачем:** HTTP Stream позволяет смотреть обмен данными в удобном виде и обнаруживать передаваемые скрипты или содержимое файлов.

В опубликованном разборе `xlm.txt` связан с обфусцированным VBScript, а `mdm.jpg` — со следующей стадией заражения. Расширение `.jpg` само по себе не доказывает, что содержимое является изображением.

## 5. Проверил сетевой адрес сервера

Для просмотра пакетов с адресом `45.126.209.4` использовал фильтр:

```wireshark
ip.addr == 45.126.209.4
```

В опубликованном разборе также упоминается порт `222`. Фактические адрес и порт необходимо подтвердить по своему PCAP.

Затем проверил регистрационные сведения об IP:

```bash
whois 45.126.209.4
```

Дополнительно можно использовать [IPinfo](https://ipinfo.io/).

**Результат из опубликованного разбора:** хостинг-провайдер — `ReliableSite.net`.

**Важно:** владелец IP-адреса или хостинг-провайдер не обязательно является автором атаки.

## 6. Восстановил файл и проверил SHA-256

Если файл извлечён из HTTP-потока или восстановлен из данных скрипта, вычислил его SHA-256:

```bash
sha256sum decoded_payload.exe
```

Имя `decoded_payload.exe` — пример; используй фактическое имя восстановленного файла.

**Хеш из опубликованного разбора:**

```text
1eb7b02e18f67420f42b1d94e74f3b6289d92672a0fb1786c30c03d68e81d798
```

**Зачем:** SHA-256 позволяет идентифицировать файл, сравнивать образцы и искать сведения о них в Threat Intelligence.

Если полученный хеш отличается, нужно проверить, корректно ли извлечены данные и не попали ли в файл лишние байты.

## 7. Проверил образец в VirusTotal

1. Открыл [VirusTotal](https://www.virustotal.com/).
2. Выполнил поиск по SHA-256.
3. Открыл раздел **Security vendors' analysis**.
4. Нашёл результат движка Alibaba.

**Результат из опубликованного разбора:** Alibaba определяет образец как `AsyncRAT`.

**Что важно:** результаты разных антивирусных движков могут различаться. Классификацию нужно рассматривать вместе с поведением файла и другими артефактами.

## 8. Проверил PE Creation Time

Для определения времени компиляции Windows PE-файла можно открыть сведения об образце в VirusTotal и найти поле `Creation Time` в разделе `Details`.

Альтернативный способ — прочитать PE timestamp непосредственно из восстановленного файла с помощью специализированного анализатора или Python-скрипта.

**Результат:** точное время нужно записать из фактически исследованного файла. Оно не указано в этом конспекте, поскольку не было подтверждено исходными данными.

**Ограничение:** PE timestamp может быть изменён или подделан и не доказывает время заражения или запуска.

## 9. Изучил обфусцированный скрипт

В HTTP-потоке изучил текст скрипта. Для упрощения чтения опубликованный разбор предлагает удалить символы `#` в соответствующей части скрипта с помощью CyberChef.

Инструмент: [CyberChef](https://gchq.github.io/CyberChef/)

Операция `Find / Replace`:
- **Find:** `#`
- **Replace:** пустая строка

Это приём для конкретного образца, а не универсальный способ деобфускации. Исходный текст следует сохранить отдельно, чтобы не потерять исходные данные.

## 10. Определил LOLBin

В опубликованном разборе в скрипте обнаружен путь:

```text
C:\Windows\Microsoft.NET\Framework\v4.0.30319\RegSvcs.exe
```

`RegSvcs.exe` — легитимный компонент .NET Framework. Использование системных бинарных файлов для выполнения подозрительных действий может затруднять обнаружение атаки.

**При проверке:** найди путь в восстановленном тексте скрипта и убедись, что он действительно присутствует в анализируемом образце.

## 11. Нашёл имена файлов, упомянутых в скрипте

В опубликованном разборе указаны следующие имена:

```text
Conted.ps1
Conted.bat
Conted.vbs
```

Назначение расширений:

| Расширение | Тип файла |
|---|---|
| `.ps1` | PowerShell-скрипт |
| `.bat` | Пакетный сценарий Windows |
| `.vbs` | VBScript |

Имена необходимо подтвердить в тексте скрипта. Не запускай эти файлы для проверки на основной системе.
